# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Tala (package `tala`, repo dir `Notely`): a local-first note-taking PWA (React 19 + Vite + Tiptap + Dexie/IndexedDB + Zustand) with handwriting ink and PDF-page annotation, also shipped as a Tauri v2 desktop app. No backend, no router.

## Commands

```bash
npm run dev          # vite dev server, :5173
npm run build        # tsc --noEmit && vite build → dist/
npm run preview      # serve dist/, :4173
npm run typecheck    # tsc --noEmit (strict, noUnusedLocals/Parameters: unused code fails the build)
npm run app:dev      # Tauri native window (needs Rust + WebKitGTK deps, see README)
npm run app:build    # Tauri installers → src-tauri/target/release/bundle/
npx cap sync ios     # after a build: copy dist/ into the Capacitor iOS project (ios/)
```

- There is no linter. `npm test` runs Vitest (`src/**/*.test.ts`, node environment, `fake-indexeddb` under real Dexie: migrations, the library write path, backups, prefs). `npm run test:smoke` (`scripts/smoke.mjs`) and `npm run test:e2e` (`scripts/pages-e2e.mjs`: per-page text, PDF import/render offline, continuous scroll, `.tala` round trip, v1/v3 upgrades, Tasks, the journal (quick capture, entry chips, suggestions), Today/Upcoming, Money, Habits, Workouts, Bituin, and the ink tools (zoom, wet ink, lasso and lasso-to-entry, page strip, PDF export, snap-to-shape), lecture audio with a fake microphone, and the coach loop (Playwright's `clock` fast-forwards writing time) in a real browser) are Playwright-core flows against a **running `npm run preview`** on :4173 (override with `SMOKE_URL`); build first. Their headers note the `LD_LIBRARY_PATH` needed for the headless shell. Each is one end-to-end flow, so there is no single-test selection. `scripts/layout-audit.mjs` and `scripts/visual-qa.mjs` follow the same preview-first pattern.
- Releases: write the `## [X.Y.Z]` section in `CHANGELOG.md`, then `npm run release -- X.Y.Z` (`scripts/release.mjs`) bumps `package.json`, `tauri.conf.json` and `Cargo.toml`, runs typecheck + tests, commits and tags locally; `git push origin HEAD vX.Y.Z` publishes. Pushing a `v*` tag runs `.github/workflows/release.yml`, which checks tag == app versions == a changelog section, runs typecheck + tests, builds the Windows Tauri installers with the changelog section as the release notes, and adds a `SHA256SUMS` file (no Linux/macOS job despite the README download table). Tag numbering continues from 2.0.0; `v1.1.0` lives on a separate line that is not in `main`.
- iOS App Store build: Capacitor (`capacitor.config.ts`, `ios/`, committed; `cap add/sync` run fine on Linux) around the same `dist/`; Tauri stays the Windows app. Dormant until the App Store launch (months away; the web app is the release). `.github/workflows/ios.yml` (macOS runner, manual only for now) archives unsigned, then signs at export with one reused Apple Distribution `.p12` plus an Admin App Store Connect API key, and uploads to TestFlight. `scripts/ios-setup.sh` is the one-time (and yearly certificate) Apple setup wizard that makes those secrets. Never change the Capacitor scheme/hostname: IndexedDB is tied to the origin. Minimum iOS 16 (`structuredClone`).
- SEO: the live site is `https://tala.lorenzmalabanan.com/` (deployed by Vercel from the web build); canonical, Open Graph, JSON-LD and the `<noscript>` text are in `index.html`, with `public/robots.txt`, `public/sitemap.xml` and `public/og-image.jpg` (cropped from `assets/tala-banner.jpg`). Keep the URL absolute there: `base: './'` does not rewrite it.

## Gotchas

- The PWA service worker precaches `**/*.{js,mjs,css,html,ico,png,svg,woff,woff2}`; keep `mjs` in that glob or the pdf.js worker is not cached and PDF import fails offline. `vite.config.js`, `vite.config.d.ts` and `*.tsbuildinfo` are untracked and gitignored: if `vite.config.js` reappears (tsc emitting `tsconfig.node.json`), delete it, because Vite loads `.js` before `.ts` and the PWA plugin would silently vanish.
- `lucide-react` is aliased to `src/lib/lucideShim.tsx`, which re-exports lucide and adds a few app-specific names (`StarFilled`, `PinFilled`, `Sort`, ...). Keep importing from `lucide-react` as usual.
- `@/` → `src/`. Tailwind colors are RGB-triplet CSS variables defined in `src/index.css` (`darkMode: 'class'`, toggled on `<html>` by `applyThemeToDom` in `settingsStore.ts`), so prefer the semantic tokens (`bg-canvas`, `text-ink`, …) over per-component `dark:` overrides.
- `README.md` is partly stale: its architecture section says repositories are the only code touching IndexedDB (it is `src/library/` now, see below), and it predates pages/ink/PDF.

## Architecture

**Library (`src/library/`) is the only code that touches note data.** `notes.ts` is the single writer of `notes`, `pages`, `inkDocs`, `blobs` and `pdfs` (create/duplicate/delete cascades, page ops, `saveInk`, `savePageContent`, `flush`). `pdfExport.ts` renders a note to PDF (see below), `snapshot.ts` holds `LIBRARY_TABLES` and drives `dump`/`restore`/`wipe`; `boot.ts` is `load`/`bootApp`/`hydrateAll`; `references.ts` repairs dangling folder/tag links and runs the folder/tag delete cascades; `safety.ts` copies a pre-v4 library into a separate `tala-safety` database before the upgrade; `migrate.ts` is the pure v4 upgrade shared by Dexie and old-backup restore. Components call library functions (`createNote`, `patchNote`, `trashNotes`, ...) directly; `noteStore`/`pageStore` are plain state and have no actions. Only `references.ts` and `notes.ts` call `useNoteStore.setState`/`usePageStore.setState`. Besides `notes.ts`: `recorder.ts` (capture) and `recordings.ts` (read side, delete, boot recovery) own `recordings`/`audioChunks` (the deletes cascade from `notes.ts`), and `study.ts` owns `meta`. `inkText.ts` is the handwriting-search experiment; it stores through `notes.setInkText`.

**Write path.** Library calls update the stores optimistically, then persist through one serialized queue (DB order == call order). A failed write rolls its change back and `toast.error`s. A note with no title, no page text and no strokes on any page is a scratch card: memory-only until it earns content, then written whole in one transaction; a note already on disk is always written, even if emptied. Ink bytes are written immediately; only the note-row `updatedAt` touch-up is debounced (800 ms per page) and flushed on `visibilitychange`/`pagehide`.

**Boot.** `App` calls `bootApp()` (`library/boot.ts`) behind the splash screen: `keepSafetyCopy()` (before anything opens Dexie), then `load()`, which reads only notes, folders, tags, pages and inkDocs, repairs references, revives ink whose note row never landed, and fills the stores. Blobs, PDFs and recordings are never loaded at boot (`load()` also reads the study days from `meta`, and `bootApp` marks recordings left `recording` by a crash as `interrupted`); `useBlobUrl` and `loadPdf` fetch them on demand. `hydrateAll()` re-runs `load()` after import/restore, and the `tala:external-sync` window event tells an open editor to resync. Navigation is state, not routes: `uiStore.activeView` + `selectedNoteId` drive the responsive three-pane `AppShell`.

**Schema changes touch several places.** `db.ts` is versioned (v1 notes/folders/tags/settings; v2 ink split into `inkDocs`; v3 `parentId`, `pages`, `pdfs`; v4 page text + `blobs`; v5 `recordings`, `audioChunks` (secondary index `recordingId`), `meta`). v3 never shipped; real users are on v2. There is no downgrade path, so migrations stay additive and are tested (`library/migrate.test.ts` seeds raw old databases). A new table needs a new `this.version(n)`, an entry in `LIBRARY_TABLES` (dump/restore/wipe follow it), the cascades in `library/notes.ts` (`deleteForever`, `clearAll`), and `utils/exportImport.ts` parsing (`parseBackup` coerces and drops malformed entries before anything touches the DB).

**Note / Page / Ink model** (easy to get wrong):
- A Note is a title, folder/tags/flags and an ordered list of `PageRecord`s (`usePageStore.pagesByNote`). **Each Page owns its Tiptap `content` and plain `text`** (the editor is keyed by page id). `Note.content` is legacy: copied to page 1 by the v4 upgrade, never written again, ignore it.
- Ink lives in the `inkDocs` table, mirrored in `useNoteStore.inkDocs`, keyed by **page id**, even though the record field is named `noteId`. The page whose id equals the note id is the legacy "page 1" (created that way, remapped by `duplicateNote`); after reordering it need not be first.
- PDF import (`library/pdfImport.ts`) keeps the original bytes in `blobs` (`PdfRecord.blobId`), stores per-page size and text layer, and pages render on demand from the original (`PageBackground.tsx`). Pages imported before v4 carry a raster in `backgroundBlobId`. Blobs are shared between a PDF note and its duplicates and are deleted when no page or PDF references them.
- A scratch card never reaches IndexedDB (`isEmptyNote` in `library/notes.ts`).

**Backups** are `.tala` zips (`manifest.json` + `backup.json` + `blobs/<id>` entries) or legacy `.json` (versions 1-3). They carry recording *rows* and `meta` (study days, weekly goal) but never audio bytes (a zip is built in memory and can crash Safari): `dump()` always returns an empty `audioChunks`, a restored lecture reads "audio not in this backup", and each lecture has its own "Save audio" download. `restore(replace)` clears local audio like everything else; old backups are upgraded to the page model on restore. Device-local prefs (pen, sidebar, reading layout) live in `store/prefsStore.ts` (zustand `persist`, key `tala:prefs`); anything that belongs in a backup must go in a Dexie table instead.

**Canvas (`src/canvas/`).** `geometry.ts` is the pure page/screen math (zoom about a point, pinch, point-in-polygon) and `lasso.ts` the lasso hit test; both are unit-tested. `ZoomColumn.tsx` wraps the editor column: a sizer takes the scaled layout size and the column is CSS-scaled from its top-left, so the scroller keeps scrolling and ink (which measures itself with `getBoundingClientRect`) stays correct. Two-finger pinch/pan uses touch events (the scroller is `touch-action: pan-x pan-y`; an active pen suspends it) and ctrl+wheel; the settled zoom reaches children through `useZoom()` (PDF re-render resolution, constant on-screen ink radii). `wetInk.ts` paints the opaque pen's in-progress stroke on a 2D canvas over the SVG (`InkLayer`), swapped for the committed SVG path on pointerup; highlighter and pencil stay on the SVG path. Only the page being written on keeps a sized wet canvas (iOS caps total canvas memory). Undo history is per note across its pages (`canvas/inkHistory.ts`, module-level, cleared by the `restore` flavour of `tala:external-sync`); `NoteEditor` owns Ctrl+Z/Y and the E/V tool keys, since several ink layers are mounted. `PageStrip.tsx` + `thumbnail.ts` draw derived thumbnails (never stored). `localStorage['tala:inkdebug']` logs pointerdown to first wet paint.

**Lecture audio** (`library/recorder.ts`, UI in `components/NoteEditor/Recordings.tsx`): `MediaRecorder.start(5000)`, every chunk goes straight into `audioChunks` and updates the recording row (so a crash at minute 6 leaves ~6 minutes playable), duration is tracked by our own clock (chunked WebM reports `Infinity`; the player scans to the end once so seeking works), a Wake Lock is re-taken on `visibilitychange`, and the mic being ended by the OS finishes the row as `interrupted`. Strokes drawn while recording carry `ts` (epoch ms); with the lasso, tapping one plays the audio from `ts - startedAt - 2 s`. The recorder takes a `RecorderEnv`, so Vitest drives it with a fake `MediaRecorder`; e2e runs it for real with Chromium's fake microphone. Untested on a real iPad: whether Safari's timesliced MP4 chunks play back when joined.

**Coach loop** (`coach/study.ts` pure, `library/study.ts` tracker): typed text and ink commits call `noteWriting()`; gaps up to 30 s count as writing, longer ones as a pause. Seconds per local day live in `meta` (`study:YYYY-MM-DD`), a Study day is 300 s, the weekly goal (`coach:weeklyGoal`, default 4) counts Monday-start weeks and never resets anything. A Session is one open note; it ends on close or after 10 idle minutes and may leave a wrap-up (minutes, pages added, unticked tasks). `coach/rules.ts` orders suggestions: wrap-up, goal cheer, install, backup, then resurfacing a note untouched for 7+ days. All strings are in `coach/copy.ts`.

**Pagtatala: entries (`src/entries/`).** The page is the record: a typed line starting with a marker is an entry (`P150 lunch gcash` money, `@ thu 2pm dentist` / `@ MWF 9-10:30 Calc` event, `[ ] essay due fri` task, `✓ water 3` tick), and roll-ups re-read every page (`scan.ts`; `listTasks` is a filter over `scanLines`), so there is no entries table. `parse.ts` holds the marker grammar and chip labels, `dates.ts` the English + Taglish date/time/repeat rules (hand-written, phrase tables in the tests). Relative words count from the day the line was written: `entryLines.ts` stamps an `at` attr on the paragraph when it first becomes an entry (user edits only, never on a `preventUpdate` reload; `keepOnSplit: false`), and shows chips as decorations. The **journal** (`library/journal.ts`) is one note per month (`Note.journal`, `YYYY-MM`) with one page per day (`PageRecord.day`), made by quick capture (`QuickCapture`, Home, Tasks, command palette); only journal pages get "confirm?" suggestions for unmarked look-alikes. Lasso → "Turn into…" stores `InkDoc.entries` (typed form + stroke ids), live while any of its strokes is. The roadmap and its decisions (all five phases built) are in `~/.claude/plans/what-if-tala-isn-t-lexical-bubble.md`.

**Agenda** (`entries/agenda.ts` pure, UI in `components/Agenda/`, `pages/AgendaPage.tsx`, Today on `HomePage`): `agenda(refs, from, days, today)` turns entries into occurrences. A task's planned day rolls onto Today once past (never overdue); only a deadline goes overdue. Repeats expand inside the window minus `skip <date>` days, until `until`; "every other" counts from the first real occurrence. Due-again (`every ~6w`) is due after the latest of its last `✓ name` tick, the date on its line, or the day it was written. The phone's tab is Today (view `home`), Upcoming is view `agenda`. Skip and Done write lines (`library/agenda.ts`). Reminders (`!`, `!15m`/`!2h`/`!1d`, untimed days count from 09:00) fire only while Tala is open on the web (`library/reminders.ts`: toast, plus a system notification when the tab is hidden and allowed); native scheduling waits for the iOS app.

**Money** (`entries/money.ts` pure, `library/money.ts` settings, `pages/MoneyPage.tsx`, a safe-to-spend card on `HomePage` once any ₱ line exists): balances, the month by category and safe to spend are re-read from the ₱ lines. Accounts, what to keep aside and per-word category choices live in `meta` (`money:accounts`, `money:keep`, `money:categories`), so backups carry them. An account is a name plus the one lowercase word you type for it; a line with no account counts toward the first one. "Has now" stores an `adjust` (actual − what the lines add up to), so later lines keep counting. `library/context.ts` pushes the account words into the parser's default context (`setEntryContext`): `parseLine`, `scanEntries` and the editor chips all read it, and `useEntries` re-scans when accounts change. Income is a repeating event with a `+` amount (`@ tuwing kinsenas at katapusan +P8000 sweldo`); safe to spend spreads (balances + spent today − keep − bills due before the next income) over the days until it, else until the month's end. Trashing a note that holds ₱ lines says so, with Undo.

**Habits** (`entries/habits.ts` pure, `library/habits.ts`, `pages/HabitsPage.tsx`, a "still to do" card on `HomePage`): a habit is a `meta` row (`habit:<id>`: name, days a week, a day's target, optional reminder time); what was done is the `✓ name [count]` lines (`x name` only for a known name, `✓ gym skip` is a day off). Strength is Loop Habit Tracker's score (`prev·m + value·(1−m)`, `m = 0.5^(√(days/7)/13)`), a day off leaves it unchanged, and for a habit kept N days a week every day of a 7-day stretch holding N done days counts as done. Study is habit #1, derived from the `study:` seconds (no data moved) with the weekly goal as its days a week. "Done"/+1 rewrites today's `✓ name N` line on today's journal page (`replaceLine` in `library/agenda.ts`) rather than adding lines. Habit names feed the parser context next to the account words; reminder times fire through `library/reminders.ts` while the habit is still to do. `clearAll` (test-only) still keeps `meta`; `wipe()` clears it.

**Workouts** (`entries/workouts.ts` pure, `library/workouts.ts`, `pages/WorkoutsPage.tsx`): a lift line (`bench 60x5x3 @8`: weight × reps × sets, optional `kg`/`lb`, `x8x3` for bodyweight, RPE) has no marker, so it is read only on journal pages: `parseLine`'s `journal` argument, set by the scanner (`Line.journal`, typed lines only), the editor chips (`day` option) and quick capture/palette previews; the ink "Turn into…" dialog passes false. The chip adds "PR" (beats every earlier day; any weight beats bodyweight, then Epley e1RM with RPE counted as reps left) or "last <day>: 3×5 57.5kg" via `chipLabel`, which reads a memoized whole-library scan. The rest timer alerts through `notify` in `library/reminders.ts` (toast, plus a system notification when hidden). Export is Strong's comma CSV (one row per set, no unit column).

**iOS app data safety (`library/mirror.ts`).** iOS can evict a webview's storage. The Capacitor app mirrors the library (backup.json format + `mirror/blobs/<id>`) into its Library folder on every background, and at boot restores it only when IndexedDB is empty *and* the `tala:mirrored` localStorage marker is gone (an eviction clears both). `wipe()` deletes the mirror first. Platform `capacitor` in `detectEnv` counts as installed; `downloadBlob` and backups go through the share sheet there (`utils/native.ts`).

**Snap-to-shape** (`canvas/snapShape.ts`, trigger in `InkLayer`): rest the pen 550 ms at the end of a stroke and a line, circle/ellipse (axis-aligned), rectangle (tilt kept, right angles exact) or triangle replaces it; anything unsure returns null and is left alone.

**Handwriting search (experiment, off by default):** `library/inkText.ts` reads handwriting line by line (`canvas/inkLines.ts`) with the browser's built-in recognizer (ChromeOS / some Android; no iPad Safari) into `PageRecord.inkText`, which search scans. The plan's downloadable TrOCR engine is deliberately not included: `@huggingface/transformers` adds ~430 MB of node dependencies (`onnxruntime-node`, `sharp` with install scripts) and a 1,000-line lockfile change, which the Windows release workflow's `npm ci` would also pull. A second `HandwritingEngine` is the extension point if that is ever wanted.

**PDF export** (`library/pdfExport.ts` gathers a note, `pdfExport.worker.ts` runs `pdfExport.core.ts` with `@cantoo/pdf-lib` off the main thread): original PDF pages are copied and ink is drawn as vector paths (`drawSvgPath`, y flipped); typed text is plain Helvetica (unencodable characters become `?`, long text continues on extra pages). The core is pure so Vitest runs it directly.

**Continuous scroll.** `NoteEditor` stacks every page in one scroll, each a `PageSheet` (its own Tiptap editor, PDF canvas and `InkLayer`). Only pages within 2 of the page in view (the last whose top is above the scroller's middle) mount their content; the rest are boxes of their last measured height (`pageHeights`). A page above the view changing height scrolls the view by the same amount (`NoteEditor`'s ResizeObserver; native `overflow-anchor` is off so the two never stack). Ink is captured from a page's top-left corner, side padding included, so typed text starts 176px down on every page: page 1's title block and the "Page N" label after it have the same height. A sheet is at least as tall as its ink doc, so ink never runs into the next page. The page last in view is remembered per device (`prefsStore.lastPages`). `addPage` copies the page above it (size, template), blank A4 under a PDF page.

**Planner frame** (`components/Planner/PlannerView.tsx`): Today, Upcoming, Tasks, Money, Habits and Workouts render through `PlannerView` (header, the hub strip `PlannerTabs` below `lg`, a body that splits into main + `aside` columns via the `.planner` container query in `index.css` at 848px) and `PlannerSection` (small-caps label + optional link; its `id` is what e2e selects on). `PLANNER_VIEWS` drives `AppShell`: with no note open, a planner view takes the whole pane on tablet/desktop (like Settings); opening a line's note puts it back in the list column beside the editor, and Back returns it to full width. The rail groups the same views under PLANNER, then NOTEBOOK (All Notes, Starred). Mobile platform baseline: Tailwind `hoverOnlyWhenSupported`, 16px inputs on coarse pointers (iOS zoom), `touch-action: manipulation` on controls.

**UI plumbing.** Modals go through `uiStore.modalStack` + `ModalHost` (singleton kinds dedupe); standalone `<Modal standalone>` overlays call `pushLocalOverlay` so global hotkeys and Esc (`hooks/useHotkeys.ts`) know a dialog is open. `NoteEditor.tsx` (~1.3k lines) hosts the page stack, the header and the pen tools (`PenBar`, `PenPalette`); `PageSheet.tsx` hosts each page's Tiptap editor and `ink/InkLayer`. Tiptap's `editor.setEditable` emits `update` unless told not to: keep the `false` argument or opening a note autosaves it.

**Desktop.** `src-tauri` wraps the same `dist/` (identifier `com.lanz.tala`; data lives in the webview's IndexedDB). Vite `base: './'` keeps the build working under `file://` and `tauri://`.
